# Cora K6-LF 独立协议

## 1. 研究问题

固定 K=6、architecture-only clustering、cluster-wise Schur 和 low-fidelity promotion 的实现，在其独立协议中产生什么 search/final 结果与额外成本？本证据不能充当与 E001 的完全 matched ablation。

## 2. 实验状态

- 搜索：完整完成，search seeds 0–4，各 300 full evaluations。
- final evaluation：完整完成，5/5 search-seed summaries；Top-7 候选各 30 replicates。
- 与 E001 的统一对照：未完成；Top-K、final epochs 和 patience 不一致。

## 3. 实验协议

| 项目 | 已核实设置 |
| --- | --- |
| dataset | Cora |
| method | K6-LF / `fixedk6_gmm_schur_lowfid` |
| search seeds | 0–4 |
| representation | K=6 diagonal GMM 在标准化 12D `z_arch` 上；5 restarts |
| selector | 完整 `z_search` 上共享 RBF kernel 的 cluster-wise Schur |
| budgets | 50 seed full + 200 candidates × 20-epoch LF + 100 promoted full + 150 qLogEI full = 300 full |
| LF equivalent | `200×20/150 = 26.67` equivalent-full |
| search training | 150 epochs、patience 40 |
| final evaluation | Top-7、30 replicates、150 epochs、patience 40；validation-only candidate selection |
| controls | 候选 pool 768、`global4`、scratch Exact GP、qLogEI；没有 matched S0/G100/G150 final protocol |

## 4. 已核实结果

- search-best validation 跨 search seeds：`.81640 ± .00261`，95% t-CI `[.81316,.81964]`。
- validation-selected candidate test mean 跨 search seeds：`.80551 ± .00518`，95% t-CI `[.79908,.81195]`。
- 全部 search histories 为 300 full；LF 固定为 200×20 epochs。

项目级数值源：[`../../results/tables.md`](../../results/tables.md)。

## 5. 统计分析

- 样本单位：5 个独立 search seeds；candidate 内 30 replicates 不作为独立搜索。
- SD/CI：`ddof=1`，df=4 的双侧 t-CI。
- paired comparison/effect size：TODO；K6 没有与 E001 匹配的 final-evaluation protocol，当前不计算无条件方法差值。
- 多重比较：不适用到单方法描述；未来 matched ablation 需预先登记。
- coverage、LF–full correlation、promotion precision：TODO。

## 6. 解释

- 直接表明：K6-LF 实现可完成五个 300-full searches 和其独立 final-evaluation protocol，且 test 未用于候选选择。
- 合理但未证明：architecture-only clustering 与 Schur shortlist 可能改变覆盖或 LF promotion 质量。
- Alternative explanations：K、clustering feature、selector、shortlist 与协议同时改变；独立 final epochs/Top-K 可解释与 E001 的差异。
- 不能推出：K6 相对 S0/G100/G150 更优/更差，或 K=6 本身产生任何收益。
